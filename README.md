# MAX Native Client

Самостоятельный нативный клиент Windows 10 x64 / Windows 11 x64 на **C# / .NET 8 / Windows Forms**. Собственные элементы Windows. **Без Electron, Chromium, WebView и загрузки интерфейса web.max.ru.** QR формируется из ссылки, полученной напрямую от MAX; после подтверждения входа клиент работает с протоколом MAX самостоятельно.

## Сборка на Linux VPS одной командой

Нужны Git, Docker Engine и Docker Compose plugin на Linux x86_64. Windows, Wine и Node.js на VPS не нужны.

Если вы уже находитесь в каталоге `max-client`:

```sh
git pull --ff-only origin main && docker compose run --build --rm build-windows
```

Для нового каталога:

```sh
git clone https://github.com/andluk87/max-client.git && cd max-client && docker compose run --build --rm build-windows
```

Команда обновляет исходники, пересоздаёт образ с .NET SDK и выпускает **dist/MAX-Native-Client.exe**. Старый образ Electron не запускается. Docker использует сеть Linux-хоста при сборке образа и контейнера, чтобы обойти наблюдавшийся тайм-аут через Docker bridge. Интернет нужен для `mcr.microsoft.com`, NuGet и их CDN. Артефакты прошлых сборок в `dist` не подтверждают успешность новой сборки: ориентируйтесь на код завершения и сообщение «Готово».

EXE self-contained, запускается без установки .NET на Windows. Установщика пока нет; при первом запуске runtime извлекает необходимые нативные библиотеки в пользовательский временный каталог. EXE не подписан сертификатом.

Скачать на Windows через SFTP либо командой на **своём компьютере** (замените адрес и путь):

```powershell
scp user@VPS:/absolute/path/max-client/dist/MAX-Native-Client.exe .
```

При распространении приложите `dist/THIRD_PARTY_NOTICES.md`.

## Вход и использование

1. Запустите EXE на Windows 10/11 x64. При отсутствии сохранённой сессии клиент напрямую запрашивает QR у MAX.
2. Отсканируйте QR мобильным приложением MAX и подтвердите вход на телефоне.
3. Выберите чат слева. Введите сообщение и нажмите «Отправить» или Ctrl+Enter.
4. Кнопка «Ранее» подгружает предыдущую страницу сообщений. Поиск фильтрует названия загруженных чатов.
5. Обновления приходят через push и периодическую синхронизацию каждые 15 секунд. «Обновить» запускает её вручную. При обрыве нажмите «Подключиться / QR».

Сессия шифруется Windows DPAPI для текущего пользователя и хранится в `%LOCALAPPDATA%\MaxNativeClient\session.dat`. Не переносите сессию между компьютерами/пользователями. Старый профиль Electron не используется; войдите повторно через QR. «Удалить сессию» удаляет её на этом компьютере; отзыв устройства выполняется в настройках MAX. Черновики сохраняются только в памяти на время запуска.

## Что реализовано

- Прямой WebSocket-транспорт с INIT/LOGIN, сопоставлением запросов/ответов, таймаутами и heartbeat.
- QR-запрос, отрисовка, опрос статуса, получение токена после подтверждения, отмена и сообщение об истечении кода.
- Ввод пароля двухэтапной защиты, если его запросит MAX.
- Собственный интерфейс списка первых 100 чатов, непрочитанные счётчики от сервера, фильтр по названию.
- Текстовая история, предыдущие страницы, имена отправителей, отправка текста.
- Push вызывает синхронизацию; периодический запрос страхует пропущенные события.
- Зашифрованное сохранение сессии, ручное переподключение и локальные черновики.

Это нативный **текстовый** клиент, не полная копия возможностей MAX. Вложения пока отображаются только названием типа. Отправка/скачивание файлов, фотографии, звонки, стикеры, реакции, уведомления Windows, создание чатов и отметка прочтения не реализованы. Список чатов ограничен первыми 100; нельзя открыть чат, который сервер не вернул в этой странице.

## Проверки и ограничения

На текущем сервере выполнена проверка прямого подключения: **INIT (6) вернул успешный ответ; QR (288) вернул qrLink, trackId, pollingInterval и ttl; опрос QR (289) и PING (1) вернули успешные ответы**. Фактический домен QR-ссылки — `max.ru`; документация также описывает `qr.max.ru`. Секретное содержимое QR и токены не выводились.

**Сборка EXE разработчиком не запускалась по просьбе пользователя.** Компиляция C#, запуск на Windows, подтверждение QR с реальным аккаунтом, загрузка переписки и отправка сообщения ещё не проверены. Неофициальный протокол MAX может измениться: успешная выдача QR не доказывает завершение авторизации. При неизвестной ошибке истёкшей сессии удалите локальную сессию и войдите снова. Не повторяйте отправку при сетевом тайм-ауте, пока не проверите историю: сообщение могло уже уйти.

Проверка после сборки: запустить на Windows 10; подтвердить QR; открыть чат; отправить тестовое сообщение и проверить его на телефоне; ответить с телефона; проверить обновление истории; загрузить старые сообщения; перезапустить EXE и проверить восстановление сессии; проверить переподключение и удаление локальной сессии.

## Протокол и авторство

`wss://ws-api.oneme.ru/websocket`, JSON ver=11. INIT 6; QR 288/289 и завершение 291 (также поддержано подтверждение 18); пароль 115; LOGIN 19; чаты 53; контакты 32; история 49; отправка 64; PING 1. Это протокол пользовательского клиента, не Bot API. TLS-проверка включена, токены и QR-ссылки не записываются в логи.

Реализация использует документацию **pr0bel1230/max-api-docs**, CC BY 4.0, и описание QR-потока в **MaxApiTeam/PyMax**, MIT; авторство, ссылка на исходную ревизию и лицензии перечислены в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md). Приложение неофициальное и не связано с командой MAX.
